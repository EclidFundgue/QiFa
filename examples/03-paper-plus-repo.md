# 示例 03：论文 + 官方实现 → 映射课程

## 用户请求

> 用 $qifa 把这篇论文和它的官方实现一起讲：arXiv 2401.00001 加上 `https://github.com/example/official-impl`，60 分钟左右，面向能读 Python 的工程师。

## QiFa 的预期行为

1. **intake**：混合输入先做相关性检查。若方法模块与代码一一对应（`relation: related`），进入映射课程；`partial` 只讲有映射的部分；`none` 则在开头询问"分开讲 / 只讲论文 / 只讲代码 / 放弃"。
2. **source-analysis**：论文侧抽取 `Eq./Fig./§`；代码侧抽取 `path:符号`；写 `relevance.mapping`（论文小节 ↔ 代码路径）。
3. **curriculum**：每章声明讲的是"论文方法 / 代码实现 / 两者映射"；时长预算按 60 分钟分配。
4. **chapter-design / visual**：公式与代码对照页成对出现；`visual-plan` 登记每个对照图的教学目的。
5. **automated-review**：来源校验确保论文引用与代码符号都存在；集成检查确保术语在论文与仓库命名冲突时以仓库为准并标注。

## 验收标准

- `relevance.mapping` 覆盖主要方法模块，且每条 `code_paths` 可解析到真实文件。
- 同一概念在论文与代码中的命名差异有术语卡说明。
- 若选择"分开讲"，则是两次独立运行（各自工作区与配置），不在同一门课里硬拼。

## 备注

- 私有仓库用本地路径输入；QiFa 只读，不安装依赖、不执行有副作用的命令。
