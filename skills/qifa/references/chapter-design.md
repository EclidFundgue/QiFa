# 章节设计（chapter-design）

目标：把章节大纲变成 `plan/chapter-plan.json`——`chapter → slide → step` 三级结构。

## 页面模型

- **chapter**：一章 = 一个学习目标 + 若干 slide。
- **slide**：一屏 = 一个页面，有页码；每页只讲一件事。
- **step**：页内逐步揭示（可选）；默认 `steps: []`，即整页一次呈现。只有"需要按顺序理解"的内容才拆 step。

`slide.kind` 枚举：`title | concept | diagram | code-walkthrough | formula-steps | video | comparison | summary`。

## 每章结构模板

1. **导入页**（`title`/`concept`）：承接上章 + 本章要回答的问题。
2. **展开页**（3–7 张）：每页一个讲点，按"直觉 → 结构 → 细节"排列。
3. **小结页**（`summary`）：本章结论 + 下章悬念。

## 讲点（points）

- 每页 1–3 个讲点；讲点是**给讲稿的骨架**（短句/要点），不是完整句子。
- 每个讲点可选挂 `source_refs`（论文编号/页码、`path:符号`）。**有引用就必须真实**；没有引用也可以（引导句、过渡句），校验器只校验"存在的引用"。
- 代码页（`code-walkthrough`）必须指定要讲的符号；禁止整文件粘贴。

## 页数预算

| 章节时长 | slide 数参考 |
| --- | --- |
| ≤ 5 分钟 | 3–5 |
| 5–10 分钟 | 5–9 |
| > 10 分钟 | 8–14 |

页码连续（`S01…`），全课程唯一；`chapter-plan.json` 的 slide id 必须与讲稿锚点（`script/NN-*.md` 的 `## S<NN>`）一一对应。

## 质量规则

- 一页一件事：出现"顺便说一下"就拆页。
- 无重复页、无空页（`points` 为空必须补或删）。
- 抽象页后必须跟具体页（例子、代码、图）。
- 页标题是结论或问题，不是"介绍/背景/总结"这类空词。
- 章节之间的过渡写在讲稿里，不单独占页（`summary` 除外）。

## 自检清单

- [ ] 每张 slide 都能对应到本章目标。
- [ ] slide id 唯一、连续、与讲稿锚点一致。
- [ ] 代码页只讲符号级片段。
- [ ] 没有一张页同时承担两个不相干讲点。
- [ ] 抽象概念至少有一个具体示例页承接。
