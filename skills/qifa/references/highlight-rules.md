# 高亮规则（定制视觉专用检查文档）

高亮只回答一个问题：**当前这条字幕在讲什么**。页面做完后，用 `scripts/highlight_audit.py` 自动重放一遍，再按文末清单人工过一遍。

## 三态

- `on`：当前焦点元素加 accent；
- `off`：其余元素压暗为陪衬；
- `neutral`：没有焦点（导入、过渡、总括）——保持原样。禁止"默认全部高亮"。

## 判定顺序（逐条字幕，自当前句向前回溯）

1. 本条是"结构讲完"句（总括 / 过渡 / 结论）→ **STOP**：中性，且此后整页不再回指高亮；
2. 本条是侧支/举例，讲完还继续 → **NEUTRAL**：本句中性，不影响前后；
3. 本条明确指向某个元素 → 高亮它（"首次介绍"就发生在这一句）；
4. 本条没有新指向、但延续上一条的主题 → 沿用最近一次的焦点（**粘滞**），不得空掉；
5. 回溯不到焦点 → 中性。

## 硬约束

- **命中序号单调不减**：一个元素介绍过之后，再出现它的关键词时**保持当前焦点**（回指不二次聚焦），`focusAt` 自动保证。
- **只有"首次介绍"用词面命中**：rules 里放该元素被引入时的说法（"第一件""第一阶段""第一步"…），不要放通用词（单个"新""n""图""时间"这类会误命中）。
- **讲点必须可命中**：讲点（points）要写成讲稿里真实出现的短语，否则该页/该点永远不高亮——`highlight_audit.py` 会把"讲点从未被高亮"判为违规。
- **通用示意图（PointFlow）的特征词规则**：跨讲点重复的 token（如 "token"）不参与匹配；候选里命中更长 token 的讲点优先（更具体者胜，平票取靠前）。讲点因此要写区别性短语，不要写通用词。
- 高亮跟随字幕，不跟随 `step`；两者冲突时以字幕为准。
- 相邻两句之间高亮只允许"不变"或"切换一次"，不允许 `on → off → on` 闪烁。

## 实现

模板 `focus.ts` 提供：`STOP` / `NEUTRAL` 哨兵、`focusAt(sentences, sentence, detect)`（含粘滞与单调保证）、`detector(rules, stops, neutrals)`（简单的 `includes` 检测器）。组件只写 `detect`，不要手写回溯逻辑。

## 自动检查

```bash
python3 <skill>/scripts/highlight_audit.py <workspace> [--quiet]
```

对每页重放判定：**组件页**用组件里的 `detector(...)` 规则，**文本页**复刻模板 `PointFlow` 的特征词匹配。报告两类违规：讲点从未被高亮、STOP 之后仍有命中；"回指已讲元素"只作 info 提示（运行期保持焦点，不影响结果）。

## 检查清单（每页逐条过）

- [ ] 每个"首次介绍"句恰好高亮对应元素。
- [ ] 承接句（"它 / 这条规则 / 这样一来"）保持上一条的焦点，没有突然变空。
- [ ] 结构讲完后的展开、举例、规则细节、结论句全部中性。
- [ ] 焦点序号单调不减、不二次聚焦；没有 `on → off → on`。
- [ ] 每个讲点都能在讲稿里找到命中的短语（不是只写给自己看的概括）。
- [ ] 导入、过渡、总括句没有被误高亮。
- [ ] `highlight_audit.py` 报 0 条违规。
