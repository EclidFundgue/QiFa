# 讲稿与叙事（narrative）

目标：把 `chapter-plan.json` 变成 `script/NN-<chapter-id>.md`——课堂口语讲稿（字幕真相源）与术语表。

## 文件格式

```markdown
# C03 论文方法：注意力机制

## S07 为什么需要注意力
讲稿正文……

## S08 缩放点积注意力
讲稿正文……
```

- 一个文件 = 一章；锚点 `## S<NN>` 与 `chapter-plan` 的 slide id 严格对应，顺序一致，不得缺页或多页。
- 锚点下就是讲稿正文（一段或几段），是字幕与后续 `narrations` 的唯一真相源。
- 代码块、公式块、图示说明可以用 Markdown 排版，但**不计入时长统计**。

## 课堂口语风格

- 像在教室里讲课：有"我们来看""这里有个坑""先别急着记公式"这类口语衔接，但不油腻、不贫嘴。
- 专业术语第一次出现：给出译名（English 原词）+ 一句定义，之后统一用译名。
- 每个新概念遵循"为什么需要 → 是什么 → 怎么用 → 边界"。
- 公式出现前先用自然语言说清它在算什么；出现后解释每个符号。
- 复杂处允许放慢（拆成短句），简单处允许一带而过。
- 禁止：书面语堆砌、AI 味排比、空话（"非常非常重要"）、无依据的断言。

## 长度与时长

- 中文 240 字/分钟、英文 130 词/分钟（可在全局配置覆盖）。
- 每页讲稿参考 = 该页预算分钟 × 语速；整章偏差超过 30% 记 warning。
- 每页讲稿建议 80–220 字（中文）：能讲 20–55 秒，配合字幕节奏。

## 过渡与节奏

- 页面之间要有口语过渡（上页结论 → 本页问题）。
- 长章中间安排一个"喘息点"（例子、图、对比）。
- 小结页回扣本章目标，而不是复述目录。

## 术语表与一致性

- 术语统一维护在 `source/source-model.json` 的 `glossary[]`：`term`（原词）、`translation`（译名）、`definition`。
- 首次出现后，全课程统一使用译名；代码标识符与数学符号不翻译。
- 论文术语与仓库命名冲突时以**仓库为准**，并在术语卡标注论文写法。
- 校验器会检查：译名是否唯一、缩写是否在 glossary 中定义。

- [ ] 朗读一遍：没有拗口长句、没有念不出来的符号串。
- [ ] 每个公式前后都有自然语言解释。
- [ ] 首次出现的术语都写了"译名（原词）"。
