# 讲稿与叙事（narrative）

目标：把 `chapter-plan.json` 变成 `script/NN-<chapter-id>.md`——课堂口语讲稿（字幕真相源）与术语表。

## 文件格式

```markdown
# C03 论文方法：注意力机制

## S07 为什么需要注意力
一句话一行，行就是一条字幕。
可以写第二行，作为第二条字幕。

## S08 缩放点积注意力
讲稿正文……
```

- 一个文件 = 一章；锚点 `## S<NN>` 与 `chapter-plan` 的 slide id 严格对应，顺序一致，不得缺页或多页。
- **拆句主权在写稿：一句话一行，行就是一条字幕**。模型/作者在写稿时决定字幕节奏，不把长句留给播放器硬切；每行应是一句完整的话（建议 20–80 字，最多两行显示）。
- 锚点下就是讲稿正文（一或多行），是字幕与后续 `narrations` 的唯一真相源；行内的句末标点仅作兜底。
- 代码块、公式块、图示说明可以用 Markdown 排版，但**不计入时长统计**。

## 课堂口语风格

- 课堂口语风格：像在教室里讲课：有"我们来看""这里有个坑""先别急着记公式"这类口语衔接，但不油腻、不贫嘴。
- 讲代码按设计思路走：这个模块为什么存在 → 它要满足什么约束 → 为什么这样选型 → 最后才是接口与实现。禁止按文件顺序朗读 API。
- 禁止抽象黑话：能用"做了什么"直说的，就不要用"契约 / 边界 / 赋能 / 抓手"这类日常不用的抽象名词；必须使用的技术术语，第一次出现时先用一句大白话解释。
- **领域专业术语直接用英文**：Transformer、flow matching、action expert、KV cache、cross-attention、action chunk、vision encoder、language backbone、tokenizer、state machine、teleoperation、proprioceptive state、episode、benchmark、dataset、policy、pipeline、ablation…一律用英文原词，**不分是否第一次出现**，不写中文译名。
- **只有论文里出现过的缩写需要"首次出现时展开"**：如 `Continuous Inference（CI）`、`Latent-aware Action Streaming（LAAS）`、`Dynamic Object Manipulation（DOM）`、`Disturbance Robustness（DR）`；论文里没有的缩写不要自造。首次展开后全篇用缩写。
- 通用叙述词保持中文（推理、延迟、观测、动作、场景、显存、真实机器人…），保证句子读得通；中英文之间留一个空格。
- 每个新概念遵循"为什么需要 → 是什么 → 怎么用 → 边界"。
- **先思想、后实现（评审反馈）**：先讲“为什么需要 / 在想什么 / 要保住什么”，再讲参数、公式与数字；数字必须挂在它要回答的问题上，禁止孤立地念数据（如“H 等于 300、K 等于 10”要先有动机与思想，再落到取值）。
- 公式出现前先用自然语言说清它在算什么；出现后解释每个符号。
- 复杂处允许放慢（拆成短句），简单处允许一带而过。
- 禁止：书面语堆砌、AI 味排比、空话（"非常非常重要"）、无依据的断言。

## 长度与时长

- 验收口径是**软范围**：讲稿总实测落在所选档位范围内即通过（短档 15–35 / 中档 30–65 / 长档 60–140 分钟）。大纲 `duration_estimate` 在写完讲稿后按实测回填，只更新数字。
- **修改讲稿的理由只能来自内容**：哪里没讲透（补展开）、哪里重复或绕（改简洁）。不允许为了贴近某个分钟数扩写废话或砍掉必要的解释；数值核对仅用于事后判断落点。
- 每页参考长度 100–360 字（约 25–90 秒）只作写作手感；页面长短服从讲解需要，讲不完就拆页，讲得完就保留。
- 深度评审自问清单（决定是否增删时逐条过）：
  - 这页每个概念是否都有“为什么需要 → 是什么 → 怎么用”？
  - 有没有某页在读稿时被跳过或一带而过（说明是凑数页或没讲透）？
  - 有没有例子被压成一句断言（说明该展开）？
  - 参数与数字是否先有动机、后有取值？（孤立念数据 → 按“思想 → 数字落在哪”重写）
  - 有没有连续几页在重复同一件事（说明该合并或删减）？

## 过渡与节奏

- 页面之间要有口语过渡（上页结论 → 本页问题）。
- 长章中间安排一个"喘息点"（例子、图、对比）。
- 小结页回扣本章目标，而不是复述目录。

## 术语表与一致性

- 术语统一维护在 `source/source-model.json` 的 `glossary[]`：`term`（原词）、`translation`（译名）、`definition`。
- 首次出现后，全课程统一使用译名；代码标识符与数学符号不翻译。
- 论文术语与仓库命名冲突时以**仓库为准**，并在术语卡标注论文写法。
- 校验器会检查：译名是否唯一、缩写是否在 glossary 中定义。
