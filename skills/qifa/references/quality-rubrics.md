# 质量 rubric 与修复策略

分两层：**脚本判定确定性项**（schema、存在性、链接、资源、构建、时长），**Agent 按本文件判定语义项**（教学、叙事、视觉、集成）。两者结果合并进 `review/qa-report.json`。

## 检查层与规则编号

| 层 | 编号前缀 | 判定者 | 检查内容 |
| --- | --- | --- | --- |
| 结构 | `STRUCT-` | 脚本 | YAML/JSON 可解析、schema 通过、阶段必需文件齐全 |
| 来源 | `SRC-` | 脚本 | 引用指向真实存在的条目；代码路径存在；媒体文件存在 |
| 教学 | `PED-` | Agent | 目标覆盖、先修顺序、深度与受众匹配 |
| 章节 | `CHAP-` | Agent | 无重复/遗漏/失衡/跳跃；每页单一焦点 |
| 叙事 | `NARR-` | Agent | 口语自然、例子充分、过渡清晰、术语一致 |
| 视觉 | `VIS-` | Agent | 每个视觉有教学目的；图表不误导；视频有替代 |
| 网页 | `WEB-` | 脚本 + Agent | 构建、链接、资源、键盘、字幕、无障碍基线 |
| 集成 | `INT-` | Agent | 术语、颜色、布局、导航、引用格式全站一致 |

## 严重级

- `blocker`：STRUCT / SRC 失败、链接断、资源缺失、构建失败、目标完全未被覆盖。必须修；`advance` 不通过。
- `warning`：语义不足、时长偏差 > `duration_tolerance`、视频缺失降级、一致性小问题。可降级发布。
- `info`：建议（措辞、可选增强）。

## 修复循环

1. `pipeline.py validate <stage>` 输出问题清单（含 `rule_id`、目标、建议修复）。
2. Agent 修复后重跑；每次失败的 `advance` 使 `attempts + 1`。
3. `attempts > max_repair_attempts`（默认 2）：
   - 若剩余问题是 blocker → 该阶段 `failed`，终止运行并说明原因。
   - 若只有 warning → 标记 `degraded`，继续推进。
4. 降级必须写 `degradations[]`，并进入 `qa-report.md` 的"降级与警告"章节。

## 语义评审问题清单（Agent 自问）

- 教学：每条目标是否真的有章节讲透？先修是否在需要前出现？
- 章节：有没有两页讲同一件事？有没有"跳过关键中间步"的页？
- 叙事：读出来像不像人在讲课？公式前后是否有解释？例子是否覆盖抽象点？
- 视觉：每个动画/视频删掉后，理解会变差吗？不会就删。
- 集成：同一术语、同一引用格式、同一配色是否贯穿全站？

## 报告

`pipeline.py report` 生成：

- `review/qa-report.json`：符合 `qa-report.schema.json`，供脚本与 Agent 读取。
- `review/qa-report.md`：人类可读版本，含摘要、逐项问题、降级与警告、时长统计、`generated_at`。

报告是交付物的一部分；存在降级时，课件首屏显示"存在降级"提示，`README-learner.md` 同步说明。

## 终止条件

- 硬错误（输入不可读、来源完全不可用、无写权限）→ 立即终止。
- 来源不足以支撑用户要求的课程 → 先降级（缩小 depth/duration）继续；连最小可用大纲都无法生成才终止。
