# 视觉设计（visual-storyboard）

目标：把章节结构与素材变成 `plan/visual-plan.json`——**登记制**：任何进入课件的视觉（图示、动画、视频、图表、代码走读、公式分步）都必须在表里写明"帮学习者理解什么"。

## 主题

三套主题（`assets/themes/`），由 `visual_style` 选择：

| 主题 | 适用 | 气质 |
| --- | --- | --- |
| `scientific-editorial` | 论文/研究 | 学术、克制、图表优先 |
| `engineering-blueprint` | 代码/工程 | 工程感、代码优先、信息密度高 |
| `classroom-clean` | 入门/通识 | 亲和、留白多、节奏慢 |

主题 = 一组 CSS token + `theme.json` 元数据；`build_site.py` 把 `tokens.css` 拷入站点。切换主题不得改章节数据。

## 登记制规则

- 每条 `items[]` 必须有 `purpose`（教学目的），写不清目的就不得进课件。
- `slide_id` 必须指向真实 slide；`asset` 指向 `source/media/` 或生成脚注说明来源。
- **不设数量上限**：多与少由教学需要决定；但每条都必须有目的，无误导性装饰。
- 视频缺失时：降级为动效/静帧图，把降级写进 `degradations`，并在 qa-report 标注（不终止）。

## 视觉类型

| type | 用途 | 注意 |
| --- | --- | --- |
| `diagram` | 结构、流程、关系 | 优先 SVG 重绘；标注数据来源 |
| `animation` | 逐步揭示、状态变化 | 只动"需要理解的部分"；可静音观看 |
| `chart` | 实验数据、对比 | 保留坐标轴与单位；不美化误导 |
| `code-walkthrough` | 代码逐步走读 | 符号级高亮；配套讲稿解释每步 |
| `formula-steps` | 公式分步推导 | 每步一句话解释；符号首次出现要定义 |
| `video` | 代码运行录屏、算法演示 | 需 poster、时长、文字替代；源文件放 `source/media/` |
| `image` | 论文原图、截图 | 标注来源编号（`[Fig.2, p.7]`） |
| `terminal-sim` | 终端/对话过程 | 只模拟真实运行过的输出；不得编造 |

## 架构图规范（论文 / 模型结构）

适用范围：模型结构、前向流程、多模块数据流——凡是"张量/形状在流动"的页面。目标是一张**常驻骨架图**，由字幕逐模块点亮。规范自包含，按下面各条即可落地。

### 1. 结构

- **沿一条前向流排布**（输入 → 编码 → 融合/主干 → 生成 → 输出），或纵向分层；同一页只用一种排布。
- 每个模块一个块，块内三行：**标题**（模块名）+ **一句职责**（它做什么）+ **形状/维度标注**（如 `4 × 384 × 384`、`36 × 960`、`20 × 32`）。
- **形状标注必须取自来源**（论文附录、配置文件、代码里的维度常量），不猜；来源写在页脚一行。
- 汇入主干的旁支输入（语言、状态…）画在主干上方，用箭头接入，边上标"投影/拼接"等动作。
- 分支与合并要能一眼看出：同一条边只表达一个语义（"通道拼接""查询 KV"）。

### 2. 尺寸与坐标

- 内容区 1136×552（1280×720 舞台扣掉内边距与字幕区）；图占其中 300–420px 高。
- SVG 一律用 **viewBox 相对坐标**（如 `viewBox="0 0 1180 356"`），外层 **`style={{ width: "100%", height: "auto" }}`**；不要写死 `height="300"`（会被等比缩到很小）。
- 块高 90–100，块间距 40–60；标题 17px、职责 13.5px、形状标注 13px（mono）；行高留 12px 以上。

### 3. 边与标注

- 箭头用 `<path>` + `<defs><marker>`；`markerEnd` 在已讲到的阶段换 accent 色。
- **边标注放在箭头下方**（`y = 箭头 y + 20`），不要放上方——上方会与相邻块标题相撞。
- 标注只写"传的是什么"（`通道拼接`、`视觉 tokens`、`查询 KV`），不写整句解释；解释留给字幕。

### 4. 配色与图例

- 模块类型用颜色区分（如 视觉编码 / 语言主干 / 动作专家 / 输入输出），颜色一律取 token（`var(--accent)`、`var(--accent-2)`、`color-mix(...)`），不写死 hex。
- 页脚给**图例**：色块 + 类型名；图例解决"哪种块是什么"，不解决"现在讲哪块"。
- 当前焦点：accent 描边 + 其余压暗（`opacity ≈ 0.35`），不靠文字解释"现在讲哪块"。

### 5. 高亮（与字幕联动）

- 图骨架常驻，**按字幕逐模块点亮**；不要整屏切换，也不要一次全亮。判定规则见 `highlight-rules.md`。
- 组件里只写 `detect`：把"首次介绍"的关键词映射到模块序号（"第一块/第二块"、"第一步/第二步"），结构讲完用 `STOP` 转中性。
- 形状/维度文本不要进 `detect`（数字会在别处复现，造成误命中）。

### 6. 代码骨架（TSX）

```tsx
const BOX_Y = 140, BOX_H = 96, ARROW_Y = BOX_Y + BOX_H / 2;
const boxes = [
  { x: 20,  w: 190, kind: "io",       title: "输入",      sub: "双视角 × 两帧", dim: "4 × 384 × 384", focus: 0 },
  { x: 250, w: 190, kind: "vision",   title: "FastViT",  sub: "vision encoder", dim: "36 × 960",     focus: 0 },
  // …后续模块 focus 依次 1、2
];
const kindFill = { vision: "color-mix(in srgb, var(--accent) 20%, var(--surface))", /* … */ };
// 渲染：boxes.map → <rect> + 三行 <text>；相邻块之间画 <path markerEnd>；页脚 <div> 放图例
```

- 形状标注与图例是**图示信息**，不得写进讲点（讲点只放关键词，受 42 字上限约束）。

### 7. 自检

- [ ] 模块顺序、连接关系与论文/代码一致，形状标注能在来源里定位。
- [ ] 一条前向流读完能复述"数据从哪来、变成什么、从哪出去"。
- [ ] 颜色与图例走 token；没有硬编码 hex；没有外部 CDN。
- [ ] 高亮只由字幕驱动，`highlight_audit.py` 0 违规。
- [ ] 无溢出：`visual_audit.py` 该页通过。

## 页面与信息密度

- 一屏一焦点；文字只作骨架，讲稿承载细节。
- 每页最多一个主视觉；图表页避免同时堆文字墙。
- 图不能只是装饰：要么解释结构，要么给出证据。

## 视频约定

- 源文件放 `source/media/`，`visual-plan.asset` 记录文件名。
- 必须提供：poster 图、时长、可选 `.vtt` 字幕、文字替代（讲稿里对应段落）。
- 视频静音可看（不混流音频）；外链视频允许但默认不用。
- v1 只嵌入，不合成、不剪辑、不录屏。

## 自检清单

- [ ] 每个视觉都有明确教学目的。
- [ ] 每个 `slide_id` 真实存在。
- [ ] 视频/图片有来源标注与文字替代。
- [ ] 动画/视频静音也能看懂。
- [ ] 没有纯装饰性动效，没有误导性图表。
